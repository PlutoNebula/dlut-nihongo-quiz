## 改动说明

### 为什么

站点的题库以前是**手工录入**的：一份 PDF 试卷要人肉抄题、抄选项、对着答案页配答案。中英日文混排 + 扫描件 + 答案单独印在卷尾（甚至没有"参考答案"标题）时，抄错、漏题、答案缺失是常态。

这个 PR 把这件事做成了一条**可重跑、可校验、可下架**的流水线：丢一个装着 PDF 的文件夹进去，出来是站点上能刷的题库卡。

### 做了什么

新增 `pdf-ocr/`（8 个脚本 + 8 个离线测试），六步 + 一个批量入口：

| 步  | 脚本            | 作用                                                                       | 花钱 |
| --- | --------------- | -------------------------------------------------------------------------- | ---- |
| S1  | `1_render.py`   | PDF → 每页 PNG                                                             | —    |
| S2  | `2_ocr.py`      | 每页**两路** OCR（StepFun + DeepSeek），逐页写 `*.review.json`             | 💰💰 |
| S3  | `3_merge.py`    | 两路比对 → 逐页 `*.merge.json`，字段规范化（答案/题型）                    | 💰   |
| S4  | `4_build_md.py` | 汇总成 `data/raw/<分类>/<分类>.md`：答案表/评分标准贴回、AI 终审、AI 解析  | 💰💰 |
| S5  | `5_check.py`    | 离线契约校验（**发布门禁**，与解析端同一套口径）                           | —    |
| S6  | `6_publish.py`  | 生成题库 + 拼接进站点源码 + 类型检查/审计/构建；**`--unpublish` 对称下架** | —    |
| S7  | `7_import.py`   | 一个文件夹 = 一个入口，逐份 PDF 串起 S1→S6；`--only` / `--from-step` 补跑  | —    |

关键设计取舍（详见 [`docs/pdf-ocr-import-guide.md`](../pdf-ocr-import-guide.md)）：

- **源 PDF 不入库**、每份卷一个独立目录；中间产物全在 `pdf-ocr/work/`（已 gitignore），只有最终 md、S5 结论、题库 JSON 入库；
- **答案以卷面为权威**：答案表/评分标准页只在"有答案"时贴回，AI 不能覆盖已有答案、不能给没有选项的题塞字母；
- **宁缺勿错**：贴不回去的答案进报告（`report.md`）而不是硬凑；S5 把"会被解析端丢弃 > 1/5"判为硬错误拒发；
- **一次失败不拖垮整批**：默认继续跑下一份；被内容审核拦截（HTTP 451）重试到头就 `⊘ 放弃本卷`（不算失败、退出码仍 0）。

## 兼容性 / 风险 / 回滚

- **不影响既有题库**：新增入口与卡片，未改动其它学科的 md/题库；`vitest`/审计/构建全绿。
- **数据可回滚**：`python pdf-ocr/6_publish.py --unpublish --entry-key marxism` 一条命令把入口与试卷从站点摘干净（原始材料默认保留，加 `--purge` 才删）。
- **答案性质**：题库为 OCR + AI 校对产物，**非官方答案**；站上对 AI 生成的解析标了 `⚙ 解析由 AI 生成（未经人工核对）`，README 的免责声明沿用。
- **重跑成本**：S1/S2/S3 有产物即跳过、S4 有续跑预检、AI 结果有缓存（`paper-review.json` / `explanations.json`），重跑一份 8 页卷量级为 S3 ≈70k tok + S4 ≈25k tok。
- **依赖**：`pymupdf`（新装）、`requests`；`.env` 增加 StepFun / DeepSeek 两组端点+密钥（`.env.example` 已更新，密钥不入库）。
